## Native Build Requirements

The current source requires CGO/native libraries without build tags:

- `faiss_wrapper/faiss.go` links `-lfaiss`; `faiss_wrapper/faiss_wrapper.cc` uses FAISS C++ APIs.
- `pkg/core/ivfpq_segment.go` uses FAISS bindings.
- `pkg/core/hnsw_segment.go` uses the USearch Go/native binding.
- `pkg/core/vec_index_manager.go` imports `C`.
- `go.mod` pins USearch commit `29e5277` to native USearch v2.25.2.

`ci/Dockerfile` is the repository's native dependency recipe: Ubuntu Noble, FAISS 1.8.0 built with shared libraries and the C API (GPU/Python/testing disabled), USearch 2.25.2 from the Linux amd64 `.deb`, OpenBLAS, CMake, and C++ tooling. It installs native libraries and runs `ldconfig`; it does not install Go. The Go binding/native USearch versions must stay aligned (`go.mod`). This is Linux amd64 guidance, not a verified macOS/arm64 or cross-compilation recipe; verify compiler, headers, linker/runtime library paths, and compatible native libraries for other environments. The old `CONTRIBUTING.md` suggestion to use `CGO_ENABLED=0` is incompatible with the current tree.

For a focused validation environment, start from that native recipe and the PR workflows above, with CGO enabled, a compatible Go toolchain, and writable disposable data paths. Recheck the relevant test configuration before enabling cluster/object-storage/WAL backends; CI's environment is not a deployment recipe. Configuration and startup prerequisites are owned by [Configuration](configuration.md).

## Generated and Data Files

Generated files, do not manually edit:

- `docs/docs.go`, `docs/swagger.json`, `docs/swagger.yaml`: generated by `swagger.sh`; `docs/docs.go` is explicitly marked generated.

Run repository-relative helper scripts from the repository root. `swagger.sh` checks for an external `swag` executable on `PATH` but does not install or pin it; the library dependency in `go.mod` does not establish the installed CLI version. `develop.sh` likewise assumes an external `reflex` on `PATH` without pinning its version. Verify the installed tools before using either script.

Embedded data assets:

- `pkg/bluge/analysis/lang/chs/gse_dict.go` and `gse_stop.go` contain large GSE dictionary/stop-word literals whose provenance is described in `pkg/bluge/analysis/lang/chs/README.md`. No repository regeneration workflow was verified; preserve provenance and verify the intended update method before changing them.

Swagger is annotation-driven and does not fully cover runtime routes. Change route/handler annotations as needed, then regenerate; validate against `pkg/routes/routes.go` `SetRoutes`.
